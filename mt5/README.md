# ⛔ ข้อสรุปสุดท้าย: กลยุทธ์นี้ไม่มี edge — อย่าใช้เงินจริง

ผลจาก **MT5 Strategy Tester ตัวจริง** บน VT Markets (XAUUSD-VIP, M1, ทุน $300,
ล็อต 0.01, `XAU_StraddleCore_v1_3`):

| ช่วงทดสอบ | ผล |
|---|---|
| 1–5 มิ.ย. 2026 | **−$37.59** (−12.5%) · 312 ไม้ · PF 0.809 |
| **1–30 มิ.ย. 2026 (เดือนเต็ม)** | **$300 → ~$185 · ประมาณ −38%** |

รอบเดือนเต็มตั้งค่าถูกหมดแล้ว — GMT ตรง (Journal ยืนยันว่าเทรดที่เซิร์ฟเวอร์
04:xx และ 16:xx ตามที่ตั้งใจ) และ Deposit Load 10% กราฟทุนขึ้นเล็กน้อยสัปดาห์แรก
แล้ว**ไหลลงตลอดทั้งเดือน** ซึ่งเป็นรูปทรงของค่าคาดหวังติดลบ ไม่ใช่โชคร้ายไม่กี่ไม้

## ตัวเลขที่ปิดเคส

คำนวณค่าคาดหวังต่อไม้จากผลรันจริง 312 ไม้:

```
ชนะ 60.6% × (+$0.84) = +$0.509
แพ้  39.4% × (−$1.60) = −$0.630
                        ─────────
ค่าคาดหวังต่อไม้      = −$0.121
```

ตรวจสอบ: `312 × −$0.121 = −$37.8` เทียบกับที่ขาดทุนจริง **−$37.59** — ตรงกันแทบเป๊ะ

**ค่าคาดหวังติดลบทุกไม้ ยิ่งเทรดเยอะยิ่งขาดทุนเร็ว** ไม่มีการจูนพารามิเตอร์ใด
แก้เรื่องนี้ได้ ต้นทุนต่อไม้ที่ล็อต 0.01 (สเปรด ~$0.29 + คอม ~$0.07 +
slippage ~$0.03 ≈ **$0.39**) กินไปเกือบครึ่งของกำไรเฉลี่ยต่อไม้ที่ชนะ ($0.84)

## ข้อผิดพลาดของการวิเคราะห์ในเอกสารนี้

ตัวเลขบวกทั้งหมดข้างล่างมาจากข้อมูล M1 **5 วันของเดือน ก.ค. 2026** ซึ่งทองขึ้น
**+2.63%** (4 ใน 5 วันเป็นขาขึ้น) ระบบ breakout ได้เปรียบมากในตลาดแบบนั้น
การจูนทุกรอบจึง fit เข้ากับสัปดาห์ที่ผิดปกติมากขึ้นเรื่อยๆ

ส่วน "นอกกลุ่มตัวอย่าง +19.4%" ก็คือ 2 วันที่อยู่ในสัปดาห์เดียวกันนั้นเอง
จึงไม่ใช่การทดสอบนอกกลุ่มตัวอย่างที่แท้จริง

**ให้ถือว่าการทดสอบ 1 เดือนของ MT5 มีน้ำหนักเหนือกว่าทั้งเอกสารนี้**

## สิ่งที่ยังใช้ได้จากงานนี้

การแก้บั๊ก 4+1 ข้อยังถูกต้องอยู่ เพราะมาจากการอ่านโค้ด ไม่ได้พึ่ง backtest:

- Scalper_TH ค่าเดิม (เสี่ยง 5% ไม่มีเพดานล็อต) **ล้างพอร์ต $300 ได้จริง**
- ระบบกลับไม้ของ StraddleReverse ไม่เคยทำงานเลย (ยิงออก 2.58%)
- บั๊ก `TimeGMT()` ในโหมด tester ทำให้ EA เทรดผิดเวลา 4 ชั่วโมงแบบเงียบๆ

## ถ้าจะไปต่อ ต้องเปลี่ยนโครงสร้าง ไม่ใช่พารามิเตอร์

| ทาง | เหตุผล |

## สรุปผล Backtest (อ่านก่อน)

ทดสอบบนข้อมูล M1 ของ XAUUSDVIP ช่วง 1–7 ก.ค. 2026 (6,526 แท่ง, 5 วันเทรด)

**ข้อสรุปสำคัญที่สุด: ตัวเลขกำไรจากการทดสอบชุดนี้เชื่อถือไม่ได้**

ทั้งสองอีเอเป็น scalper ที่ตั้ง trigger ห่างเพียง \$0.50–\$1.00 และไล่ SL ที่ระดับ \$1.00
ซึ่งเล็กกว่าช่วงแกว่งภายในหนึ่งนาที ผลลัพธ์จึงขึ้นกับ "เส้นทางราคาภายในนาที"
ที่ข้อมูล M1 **ไม่ได้บันทึกไว้** — คอลัมน์ `TICKVOL` บอกว่าช่วงนั้นมีติ๊กจริง
2,574,976 ติ๊ก แต่ไฟล์เก็บไว้แค่ 6,526 แถว คือข้อมูลราคาหายไป 99.75%

### หลักฐานที่ 2 — Control test (ชี้ขาด)

สร้างข้อมูลที่มีความผันผวนและสเปรดเท่าเดิมทุกประการ แต่**สลับลำดับราคาแบบสุ่ม**
เพื่อทำลายโครงสร้างตลาดจริง อีเอที่มี edge จริงต้องกำไรหดเหลือใกล้ศูนย์

| | ข้อมูลจริง | สุ่ม #0 | สุ่ม #1 | สุ่ม #2 |
|---|---|---|---|---|
| EA A | +11,084 | +5,724 | +4,561 | +4,468 |
| EA B | +6,973,277 | +7,907,038 | +6,021,394 | +6,613,220 |

**EA B ทำกำไรบนข้อมูลสุ่มได้พอๆ กับข้อมูลจริง** → กำไรมาจาก artifact ของการจำลอง
ไม่ใช่ความสามารถในการอ่านตลาด EA A เป็นแบบเดียวกันแต่รุนแรงน้อยกว่า

## รายการแก้ไข

ทั้ง 4 ข้อมาจากการอ่านโค้ด **ไม่ได้พึ่งผล backtest** จึงยืนอยู่ได้โดยไม่ขึ้นกับข้อจำกัดข้างบน

### EA A — `XAU_StraddleReverse_v4_4.mq5`

#### 1. ระบบกลับไม้ (Reverse) ยิงไม่ออกทางคณิตศาสตร์ ← ข้อร้ายแรงที่สุด

ฟีเจอร์เรือธงของ v4 ไม่เคยทำงานเลยด้วยค่าดีฟอลต์เดิม:

- `InpBEStart = 0.80` → กำไรถึง \$0.80 เลื่อน SL ไป `ทุน + 0.20`
- `InpReverseGap = 1.20` → วางไม้ดักที่ `bid − 1.20` = `ทุน − 0.20`
- SL อยู่**สูงกว่า**ไม้ดัก \$1.40 → ราคาย้อนกลับก็โดน SL ก่อนเสมอ
- พอ trailing ทำงาน: SL = `bid − 1.00` แต่ไม้ดัก = `bid − 1.20` → SL ชิดกว่า \$0.20 **ตลอดเวลา**

**แก้:** เพิ่ม `ResolveReverseGap()` บังคับให้ระยะไม้กลับแคบกว่าระยะ SL ที่คุ้มครองอยู่เสมอ
เพดาน = `min(InpTrailDist, InpReverseStartPts − InpBELock) × 0.75`
พร้อมเปลี่ยนค่าดีฟอลต์ `InpReverseGap` 1.20 → 0.60 และเพิ่ม `InpAutoFixReverseGap`
(เปิดไว้) กับข้อความเตือนใน Journal เมื่อค่าที่ตั้งขัดกันเอง

ผลจาก simulator — ไม้กลับถูกชนจริง:

| | ยิงออก |
|---|---|
| `InpReverseGap = 1.20` (เดิม) | 41 / 1,592 ไม้ = **2.58%** |
| `InpReverseGap = 0.60` (ใหม่) | 1,418 / 2,664 ไม้ = **53.23%** |

> ตัวเลข % นี้เป็นข้อพิสูจน์เชิงกลไกว่าฟีเจอร์ทำงานแล้ว
> ไม่ใช่การอ้างว่าทำกำไรได้ — เรื่องกำไรยังต้องรอ tick data

#### 2. `CalcLot()` ไม่รู้ว่า SL ถูกโบรกขยาย

`PlaceBuyStop()` / `PlaceSellStop()` ขยาย SL เป็น `IMax(ToPts(InpStopLoss), MinStopPts())`
เมื่อโบรกกำหนดระยะขั้นต่ำกว้าง แต่ `CalcLot()` ยังคำนวณล็อตจาก `ToPts(InpStopLoss)` เดิม
→ **ความเสี่ยงจริงเกิน `InpRiskPercent` ที่ตั้งไว้แบบเงียบๆ**

**แก้:** เพิ่ม `EffectiveSLPts()` เป็นแหล่งความจริงเดียว ใช้ทั้งตอนวางออเดอร์
ตอนคำนวณล็อต และตอนเลื่อนราคาออเดอร์ดัก

### EA B — `XAUUSD_Straddle_Scalper_TH_v3_1.mq5`

#### 3. ไม่มีเพดานล็อต + เสี่ยง 5% ต่อไม้

```mq5
InpRiskPercent = 5.0
lot = MathMax(minLot, MathMin(maxLot, lot));   // maxLot = เพดานโบรก ไม่ใช่ของผู้ใช้
```

จาก simulator: ไม้แรก **2.00 ล็อต** → ไต่จนชน **100 ล็อต (เพดานโบรก)**
→ **ขาดทุนไม้เดียว −\$25,000** และภายใต้สมมติฐานที่หยาบขึ้นก็**ล้างพอร์ตทั้งหมด**

**แก้:** เพิ่ม `InpMaxLot = 0.50` (0 = ใช้เพดานโบรก) และเตือนใน Journal ตอนเริ่มทำงาน
เมื่อ `InpRiskPercent > 2.0`, เมื่อไม่ได้เปิดเพดานขาดทุนรายวัน และเมื่อปิด Time Filter

> ค่า `InpRiskPercent` เดิม (5.0) **ไม่ถูกเปลี่ยน** — เป็นการตัดสินใจของผู้ใช้
> เพดานล็อตทำหน้าที่เป็นตาข่ายรองรับแทน (พอร์ต \$10,000 → ขาดทุนสูงสุด/ไม้ = \$125 = 1.25%)

#### 4. ไล่ SL ฝั่ง Buy/Sell ไม่สมมาตร (นับสเปรดซ้ำ)

```mq5
// เดิม
BUY : lockSL = bid - 100*pt                              → ห่าง 100 จุด
SELL: lockSL = ask + (100 + max(30, spread))*pt          → ห่าง 130 จุด
```

ไม้ขายปิดที่ `ask` ซึ่งรวมสเปรดอยู่แล้ว การบวก `InpSpreadCompPts` เข้าไปอีกคือนับซ้ำ
→ ไม้ Sell ถูกไล่หลวมกว่าไม้ Buy ราว 30 จุดโดยไม่ตั้งใจ เกิดที่ candle trailing ด้วย
(`prevLow − 50` เทียบกับ `prevHigh + 80`)

**แก้:**
- **ไล่ตามราคาสด** — วัดจากราคาปิดของแต่ละฝั่งด้วยระยะเท่ากัน (`bid − gap` / `ask + gap`)
- **ไล่ตามแท่งเทียน** — คงการชดเชยสเปรดฝั่งขายไว้ เพราะแท่งเทียน MT5 อ้างอิง Bid
  แต่ไม้ขายปิดที่ Ask จึงต้องแปลงหน่วยจริงๆ **แต่ใช้สเปรด ณ ขณะนั้น**
  แทนค่าคงที่ 30 จุดที่เหมารวมไว้เดิม
- `InpSpreadCompPts` เปลี่ยนความหมายเป็น "บัฟเฟอร์เสริมที่ใส่เท่ากันทั้งสองฝั่ง"
  ค่าดีฟอลต์ 30 → **0**

## เครื่องมือ backtest

Simulator ภาษา Python ที่จำลองตรรกะคำสั่งของทั้งสองอีเอแบบบรรทัดต่อบรรทัด
(วาง pending, OCO, BE, trailing, reverse, cooldown, time filter, การคำนวณล็อต)

| ไฟล์ | หน้าที่ |
|---|---|
| `bt.py` | เครื่องยนต์หลัก + คลาส `EA_A` / `EA_B` + การรายงานผล |
| `path.py` | ตัวสร้างเส้นทางราคาภายในแท่ง (พารามิเตอร์ `noise`) |
| `control.py` | สร้างชุดข้อมูลควบคุมแบบสลับลำดับ |
| `sweep.py` | ทดสอบความไวต่อ noise + control test |
| `sweep2.py` | เทียบแบบล็อตคงที่ + ทดสอบต้นทุน + วิเคราะห์ reverse/ล็อต |
| `sweep3.py` | ความไวต่อ timezone + ผลรายวัน |

รัน: แก้ path ของ CSV ในตัวแปร `CSV` ใน `bt.py` แล้ว `python3 sweep.py`

**สิ่งที่ต้องทำต่อ:** ป้อน real tick data (คอลัมน์ BID/ASK ระดับมิลลิวินาที)
เข้าไปแทน แล้วพารามิเตอร์ `noise` กับการเดาเส้นทางราคาจะหายไปทั้งหมด
